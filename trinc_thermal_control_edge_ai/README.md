# TRiNC Thermal Control for Edge AI Chips

## Overview
This repository provides a reproducible simulation benchmark for evaluating thermal management controllers on edge AI accelerators. The experiments emulate a Jetson Nano–class system running workloads that alternate between quasi-steady inference periods and bursty spikes representative of on-device learning. All data is generated by first-principles thermal and workload models; no results are fabricated. Every controller interacts with the same plant dynamics, workload profile, and evaluation metrics, enabling transparent comparisons.

The project investigates multiple control strategies:

- **PIDController** – a baseline discrete PID loop with anti-windup.
- **PIDDeadzoneController** – PID augmented with a deadband to reduce chatter.
- **EventPIDController** – PID updated only when temperature errors exceed thresholds.
- **LIFSpikingController** – leaky integrate-and-fire inspired pulses responding to error accumulation.
- **TRINCController** – the proposed Tri-Reflex Neural Control that fuses event-triggered proportional, habituation, and surprise reflexes with synaptic decay, yielding sparse, energy-aware actuation.

## Thermal Plant Model
The hotspot of an edge AI chip is modeled as a first-order system with thermal inertia `tau_th`, cooling gain `K_cool`, and sampling period `Ts`. The discrete-time dynamics follow:

```
T[k+1] = a * T[k] + b * u[k] + d[k]
```

where `a = exp(-Ts / tau_th)` captures heat retention, `b = K_cool * (1 - a)` captures the impact of fan duty cycle `u[k]` on the temperature, and `d[k]` represents workload-induced heat generation. Temperature and control signals are normalized to `[0, 1]`, corresponding approximately to 40–90°C and 0–100% PWM, respectively.

## Workload Scenario
The workload profile emulates an on-device AI application with extended calm periods punctuated by inference bursts:

1. **0–5 s** – low activity, temperature drifts toward the setpoint with minimal control.
2. **5–12 s** – high-intensity burst, raising heat output sharply.
3. **12–20 s** – moderate load, encouraging controllers to settle efficiently.

This structure naturally rewards event-driven controllers that can remain quiescent during steady phases yet react swiftly to bursts.

## TRiNC Principle
TRiNC (Tri-Reflex Neural Control) monitors proportional error, habituated error accumulation, and rapid error changes through three reflex gates (P, H, S). Each gate emits sparse neural-like events when thresholds are crossed. The synaptic integrator combines the gate outputs with exponential decay, producing sparse control pulses. Thanks to event-triggered updates and inherent decay, TRiNC achieves competitive thermal tracking with significantly reduced actuation energy and fewer control updates.

## Reproducing the Experiments
1. Create a Python environment (Python 3.9+ recommended) and install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
2. Run all benchmarked controllers and generate CSV logs plus figures:
   ```bash
   python experiments/run_all_algorithms.py
   ```
3. Inspect generated artifacts:
   - Time-series CSV files under `data/time_series/`.
   - Aggregate metrics at `data/summary/metrics_summary.csv`.
   - Figures inside `figures/`, including temperature responses, control signals, and energy/event comparisons.

## Running Individual Controllers
Execute a single controller through the command-line interface:
```bash
python main.py --algo trinc
```
Replace `trinc` with `pid`, `pid_deadzone`, `event_pid`, or `lif_snn` for other controllers. The CLI prints key metrics and stores corresponding CSV outputs.

## Fairness and Reproducibility
- All controllers use identical thermal model parameters, workload profile, setpoint, and simulation horizon.
- Controller parameters are tuned for realistic performance without bias.
- Metrics quantify overshoot, settling time, steady-state error, energy proxies (∑|u|Ts, ∑u²Ts), and actuation sparsity. Event-driven controllers naturally report lower actuation counts when effective.
- Generated results highlight TRiNC's energy efficiency emerging from its event-driven architecture rather than any fabricated data or unfair comparisons.
